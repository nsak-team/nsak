Figure~\ref{fig:benchmark_duration_cyberlab} shows the mean run duration per configuration.
The multi-agent setup completes in 318\,s on average, while the unstructured output scenario

The extended duration of the unstructured variant stems from its tendency to produce lengthy
free-form responses before each tool invocation, increasing overall wall-clock time without
a proportional gain in coverage.

Figure~\ref{fig:benchmark_tokens_cyberlab} visualises mean token consumption.
The unstructured output scenario consumes 222,094 tokens on average, nearly three times the
81,453 tokens used by the multi-agent configuration.
This difference reflects the verbosity of unstructured reasoning traces compared to the
focused, schema-constrained outputs of the multi-agent setup, where each sub-agent exchanges
only the information necessary for its specialised task.

\subsection{Qualitative Criteria}\label{subsec:qualitativ-criteria-cyberlab}

The evaluation criteria and scoring scale are defined in Table~\ref{tab:qualitative-scale}.
The Cyberlab BFH segment does not feature a single staged vulnerability with a binary
pass/fail verdict as the Containerlab scenario does.
Instead, the discriminating findings are distributed across the infrastructure and require
active tool invocations beyond a basic TCP port scan.
Three findings serve as quality indicators:

\begin{enumerate}
    \item \textbf{\acrshort{SNMP} community \texttt{public}} on the Cisco router
          (\texttt{193.5.80.250}) and the MikroTik device (\texttt{193.5.80.181}).
          Querying this community discloses the full system description and, in the case of the
          Cisco appliance, reveals an end-of-life \acrshort{IOS} version 12.4(23) from 2008 --
          a significant operational risk invisible without UDP enumeration.
    \item \textbf{Open DNS recursion} on five \acrshort{BIND} servers
          (\texttt{.20}, \texttt{.78}, \texttt{.80}, \texttt{.185}, \texttt{.186}).
          Without explicit \texttt{dns-recursion} and cache-snoop \acrshort{NSE} scripts the
          resolvers appear as benign authoritative servers; with them, they are confirmed open
          relays susceptible to amplification attacks.
    \item \textbf{Cloned \acrshort{SSH} host keys} shared between hosts
          \texttt{.182}, \texttt{.185}, and \texttt{.186}, which were deployed from the same
          image without regenerating keys.
          This is only discoverable through \texttt{ssh-hostkey} fingerprint comparison across
          all three hosts simultaneously.
\end{enumerate}

\textbf{claude-opus-4-7 in multi-agent mode} achieves a correctness score of 7.
In the five successful runs the model consistently identifies the six high-severity structural
risks present in the network: legacy cryptography on the Cisco router and MikroTik device,
Webmin exposed on five \acrshort{QEMU} router hosts, world-accessible \acrshort{NFS} exports
on the Synology \acrshort{NAS}, \acrshort{SMB} message signing disabled on the Windows host
and the \acrshort{NAS}, and the MySQL instance bound to a non-loopback interface.
All findings are accompanied by severity ratings and actionable remediation steps.
However, none of the successful runs includes \acrshort{UDP} enumeration, so the \acrshort{SNMP}
community \texttt{public} on the Cisco and MikroTik devices is never discovered.
Similarly, \texttt{dns-recursion} and \texttt{ssh-hostkey} comparison scripts are absent from
most runs, leaving the open resolver risk and the cloned key finding unexplored.
The hallucination score is 9: every claim in the final reports is directly traceable to
\texttt{nmap} \acrshort{NSE} output, with no fabricated CVE identifiers or version numbers.
A notable reliability concern is the high error rate of the multi-agent setup --
only 5 of 27 attempts produced a fully structured result.
Shorter successful runs (84--190\,s, 4--8 tool calls) performed only a ping sweep without
port scanning, yielding host-layer data with no service coverage.

\textbf{claude-opus-4-7 in unstructured output mode} achieves the highest correctness score of
9 among the \acrshort{AI} configurations.
When successful -- six runs out of 109 attempts -- the model issues \acrshort{UDP} scans
alongside \acrshort{TCP} and discovers \acrshort{SNMP} \texttt{public} on both the Cisco router
and the MikroTik device, allowing it to identify the end-of-life Cisco \acrshort{IOS}~12.4(23).
It also runs \texttt{dns-recursion} and \texttt{dns-cache-snoop} scripts, confirming open
recursion on all five \acrshort{BIND} instances.
The \texttt{ssh-hostkey} sweep across all hosts reveals the shared key fingerprint between
\texttt{.182}, \texttt{.185}, and \texttt{.186}.
In addition, the model discovers a previously uncatalogued \acrshort{ESXi} host at
\texttt{193.5.80.194} through port~902 (\texttt{VMware Authentication Daemon 1.10}), a host
absent from the reference run.
The hallucination score is equally 9: all assessment statements are grounded in concrete scan
artefacts.
The main limitation of this configuration is its very low success rate (5.5\,\%) and the
substantially higher token cost (mean 222\,094 tokens), driven by the unstructured reasoning
traces produced before each tool call.

\textbf{qwen3:8b} in the local multi-agent setup scores 1 for correctness.
Across all six attempted runs the model reads the host configuration but issues zero
\texttt{cli\_tool} calls.
Without executing \texttt{nmap} or any equivalent utility the model produces a generic
fallback report citing connectivity issues and recommending manual verification.
No actual reconnaissance is performed, making a hallucination assessment meaningless.
