\section{Framework Comparison}\label{sec:framework-comparison}
Previous research, such as \enquote*{SOK: A Survey of Open-Source Threat Emulators},
compares multiple types of threat emulation frameworks using both quantitative and qualitative metrics~\cite{Zilberman2020SoKThreatEmulators}.
Among the evaluated frameworks, Atomic Red Team, Mitre Caldera,
and Metasploit received high scores in the categories \enquote{environments and operator}, \enquote{environment configuration} and \enquote{scenario execution}.

In the following section, the selected frameworks are briefly introduced, and the unique selling point of the \gls{NSAK} is highlighted.
As a point of reference, the cybersecurity community increasingly relies on the concepts of MITRE ATT\&CK,
which has established itself as a standard framework in the field since its introduction in 2014~\cite{mitreattack, alsada2023attack}.

The MITRE ATT\&CK framework is a globally accessible knowledge base of adversary tactics and techniques based on real-world observations~\cite{mitreattack}.
The knowledge base is structured into \gls{TTP}, which are organized into 14 attack behavior groups.
The \gls{TTP} is getting continuously updated and extended, which helps to defend against the capabilities of threat actors.

The evaluation of the proposed frameworks is based on information obtained from official documentation~\cite{caldera,atomicredteam,metasploitdocs} and the findings of Zilberman et al.~\cite{Zilberman2020SoKThreatEmulators}.

As shown in table~\ref{tab:framework-comparison}, the key characteristics of the frameworks differ greatly.
\textbf{Atomic Red Team} provides libraries of attack scripts that implement individual \gls{TTP} of MITRE ATT\&CK.
Each attack can be executed independently or chained together into a larger attack scenario.
\textbf{Mitre Caldera} is a complex, agent based adversary simulation tool,
whereas \textbf{Metasploit} is a framework that provides exploits, payloads and auxiliary modules.

\subsection{Atomic Red Team: Features and Capabilities}\label{subsec:atomic-red-team-evaluation}

The Atomic Red Team repository provides documentation and configuration files for each technique.
For every TTP, a \gls{YAML} configuration file defines the execution parameters, while an enhanced Markdown file contains a human-readable description of the attack.
This documentation includes a short description of the technique, execution instructions, and additional contextual information~\cite{atomicredteam}.

The framework can be executed directly from the command line and provides features such as logging, detailed error messages, and automatic prerequisite checks.
If a technique cannot be executed, for example due to operating system constraints, the framework reports the issue and can optionally attempt to install the required prerequisites~\cite{atomicredteam}.

\textit{Zilberman et al.} recommends deeper cybersecurity knowledge to use Atomic Red Team framework effectively~\cite{Zilberman2020SoKThreatEmulators}.
The Open Source mentality, expandability and easily usable scripts can be a great asset for an independent framework such as the \gls{NSAK}.


\subsection{Caldera: Features and Capabilities}\label{subsec:caldera-evaluation}

Mitre Caldera is also built on the MITRE ATT\&CK knowledge base and functions as a command-and-control center.
A central server controls agents running on the target system, executes attacks called abilities, and sends the operation results back to the server.
Every Ability is a single attack step built on the \gls{TTP}.
The framework ships with a graphical user interface and is primarily used for red team attack simulation, purple teaming, and detection engineering.
The additional features, like a training plugin for educational purposes, include facts that can be configured as dynamic safe values, which can be stored and parsed in later steps~\cite{caldera}.

With its provided interface and functionality, Caldera is most suitable as a threat emulator,
offering a wide range of built-in features, including lateral movement and \gls{CNC} communication~\cite{Zilberman2020SoKThreatEmulators}.

\subsection{Metasploit: Features and Capabilities}\label{subsec:metasploit-evalutaion}

Metasploit is a widely used penetration testing framework for testing or attacking systems and exploiting known vulnerabilities.
Metasploit follows a sequence of steps to identify a vulnerability in a target system, select a vulnerability for the attack,
select an exploit that uses this vulnerability, and deliver a payload that runs on the target system.
The configuration via the \gls{CLI} requires knowledge of the target network and system and requires partial configuration~\cite{metasploitbook, metasploitdocs}.

According to Zilberman et al., an operator requires extensive cybersecurity knowledge to effectively use the framework.
To support the operator, the \gls{GUI} \enquote{Armitage}, which is not further evaluated in this work, can be used~\cite{Zilberman2020SoKThreatEmulators}.


\subsection{\gls{NSAK: Features and Capabilities}}\label{subsec:nsak-usp}
The \gls{NSAK} framework, as an independent universal Network Swiss Army Knife,
was implemented with a strong focus on networking and hardware devices in mind.
This is underlined by the provided resource types, such as the network environment~\ref{subsec:environment-concept},
device~\ref{subsec:device-concept} and the reference hardware evaluated in the predecessor project~\ref{sec:predecessor-project-project-2}.
The scenarios~\ref{subsec:scenario-concept} and drills~\ref{subsec:drill-concept} are implemented as simple Python scripts,
with a few conventions instead of extensive boilerplate code or complicated concepts.
Even though the framework can not compete in terms of maturity and library size,
the modular design allows to incorporate the tools of other frameworks as drills if we see fit.
An example could be, to use an \gls{AI}-Enhanced Network Discovery Scenario,
which provides the necessary information to configure a Metasploit attack that leads to an attack operation in Caldera or an Atomic Red Team detection script.
Further, the framework provides container based isolation, scenario simulation in virtual environments and flexible positioning in physical labs.
In summary \gls{NSAK} can be seen as a harness for network focused cybersecurity attack and defense scenarios,
which should help reduce the operational costs of red and blue teams~\cite{nsakRepository2026}.


\section{AI Research}\label{sec:ai-research}

\subsection{AI and Language Models}\label{subsec:ai-and-language-model}

\gls{LM} describes the technique for advancing language intelligence in machines and its development history can be divided into several stages.
The first stage, \gls{SLM} emerged around the 1990s, and the basic idea is to assume, that such a model can predict the next word.
But the fact that an exponential number of transition probabilities are needed, caused a lack of accuracy and led limited success.

To overcome these limitations, \gls{NLM} was introduced to learn a distributed representation of words and capture more complex patterns, leading to a major breakthrough.
Building on this, the advancement of pre-trained language models \gls{PLM}, which are first trained on large datasets and then fine-tuned for specific tasks, represented another significant development.

Building on this development, \gls{LLM}s further increases the scale of \gls{PLM}s by expanding parameter count and computational power~\cite{zhao2023survey}.

In large language models, parameters are the trainable numerical values that define how the model processes input and generates output.
During training, these parameters are continually adjusted to enable the model to learn patterns and language context~\cite{shoeybi2020megatronlmtrainingmultibillionparameter}.
The models most of us use today, such as ChatGPT, Claude and Gemini are pre-trained \gls{LLM}s used for language inference.

These advances led to \gls{MCP}, a protocol that allows tools and services to expose an interface specifically for \gls{AI}.
Further, the introduction of \gls{AI}-agents is enabling a new level of autonomy for achieving concrete goals such information gathering, task automation, or multistep problem-solving with \gls{LLM}s.
The combination of specialized \gls{LLM}s, \gls{MCP}-based tool integration is now resulting in systems, where \gls{LLM}s empower autonomous agents capable of decision-making to execute complex tasks.

\subsection{\gls{MCP}}\label{subsec:mcp}

\gls{Anthropic}, a US software company focused on \gls{AI} research, introduced the protocol in 2024.
The \gls{MCP} was introduced as an open source standard that enables \gls{AI} assistants to connect to external systems, including databases, business tools, and development environments~\cite{anthropic-mcp}.
Dynamic tool discovery and schema negotiation is helping clients and agents to access these functions in a standardized manner and allows autonomous interaction.
Additionally, \gls{MCP} allows information to flow in both directions, so the model can send requests, and tools can send updates or events.

This architectural approach shifts the \gls{AI} integration from static toward an interoperable ecosystem of \gls{AI}-enabled services.
On the other hand, the flexible design and open source approach of \gls{MCP} unlocks multiple novel and systematic security risks, including insecure tool integrations and prompt injection via external data sources that are in need of enhanced security and governance~\cite{hasan2025modelcontextprotocolmcp}.

\subsection{Agentic-AI}\label{subsec:agentic-ai}

\gls{AGENTIC-AI} is defined as an advanced machine intelligence that is capable of perceiving, reasoning, and acting with a certain level of autonomy.
Traditional systems and agents are more limited to executing predefined commands, whereas \gls{AGENTIC-AI} is not restricted in this way.
Due to their ability to adapt in real time, they can continuously refine their knowledge, techniques, and data.
The ability to access multiple inputs, from natural language processing to sensor data, allows \gls{AI AGENT}s to develop a good understanding of their environment~\cite{chapter1}.

\gls{MAS} defines a way in which multiple specialist agent coordinate and cooperate with each other to solve a task, that would not be solvable to one agent alone.

Therefore, the agents need a form of interaction that allows them to act reactively, often through a shared mental model, which helps create a common understanding of the complex tasks to be solved.
To implement a \gls{MAS} efficiently, modern design principles such as encapsulation and modularity are important, which are helping to balance resource usage of the system and \gls{LLM}~\cite{chapter3}

Huang et al. provide evidence that \gls{AGENTIC-AI} and \gls{MAS} are capable of solving complex tasks across various sectors, including security and banking.
However, these systems also introduce new potential vulnerabilities, both within \gls{AI AGENT} systems themselves and through their interactions with external environments.

The identified vulnerabilities can be categorized into two types: accidental and deliberate.
Accidental vulnerabilities include software bugs, logical errors introduced by agents, hardware malfunctions, and poor data quality.
Deliberate attacks, on the other hand, encompass adversarial attacks targeting \gls{LLM}s, data poisoning, and model theft.

To mitigate these risks, a comprehensive framework consisting of governance mechanisms,
proactive monitoring, regulatory compliance, and rigorous testing is required to ensure the secure and reliable operation of agentic systems~\cite{chapter12}.

\subsubsection{Conclusion: Tool Calling \& Agentic \gls{AI}}\label{subsubsec:mcp-is-dead}

In the cybersecurity podcast Risky Business, it is mentioned that \gls{MCP} is \enquote{dead}.
The open-source strategy of \gls{Anthropic} (\ref{subsec:mcp}) has led to the development of multiple \gls{MCP} implementations that were not designed with a strong focus on security,
but rather on rapid adoption of a novel technique.

This claim is based on the observation that, when faced with excessive \gls{MCP} tooling, \gls{AI} agents may resort to direct access to a root shell, which provides a more efficient way of interaction~\cite{riskybiz_mcp}.
Recently, other concepts for calling tools were established, such as .
These observations are directly relevant to this thesis,
singe the \gls{AI}-based scenarios will heavily rely on tool usage,
and this thesis focus to restrict the agent to \gls{MCP} based tools.
Consequently, from now on this thesis focus on the more general concept of \textbf{Tool Calling} instead.

Another limitation of tool usage is that tools must be described to the \gls{LLM}, which
increases input token consumption and consequently the required context size.
Depending on the model, its size and the available hardware resources,
this can lead to descriptions filling a significant portion of the context window,
degrading the overall performance and quality of the responses.
The architectural decision is not to remove tools completely,
but instead to expose a minimum set and an overview of available capabilities.
An \gls{LLM} can now request a tool description from the agent,
after it decided that it needs this capability
~\textthreequartersemdash~this is called dynamic tool selection.

\subsubsection{Evaluated Frameworks and Tool Calling}

Caldera uses a \gls{MCP} plugin as a bridge between the model and the \gls{REST API},
allowing the agent to plan and issue commands in a manner similar to a human operator.

Caldera introduces three main research areas.
First, a planner determines the order and selection of abilities and can dynamically construct new adversaries based on user requirements through prompt-based interaction.
Second, an adversary factory model generates adversaries tailored to the operator's specific use cases.
Lastly, a forward-deployed agent is enhanced with \gls{RAG} for \gls{CTI}, leveraging \gls{STIX}-based data to create reproducible and testable adversaries~\cite{caldera_mcp_blog}.

The \gls{MCP}-Server, provided by \textbf{Metasploit}, enables a \gls{LLM} to interact with the Metasploit Framework dynamically.
The Interface covers module information (a Metasploit module is a known exploit), exploitation workflows, payload generation,
session management and handler management to help manage an attack.
The documentation includes a security warning that emphasizes the importance of reviewing every prompt,
using a test environment, and being aware of post-exploitation commands.
\textbf{Metasploit} is a powerful exploitation framework, and the simplicity that \gls{AI} could bring can also harm~\cite{metasploit_mcp}.

The \textbf{Atomic Red Team} \gls{MCP} Server provides an interface that allows \gls{AI} systems to access and use tests from Atomic Red Team.
It enables searching, validating, and optionally executing attack techniques
~\textthreequartersemdash~e.g., based on MITRE ATT\&CK~\cite{atomic_red_team_mcp}.

\subsubsection{Comparison Outcome \& Framework Choice}\label{subsubsec:outcome}

The framework comparison highlights the difference between \gls{NSAK} and the established frameworks.
Each compared framework has its own focus and is able to perform a specific task in a complex operation.
This thesis focuses on the \gls{NSAK} framework for the following reasons.
\paragraph{Network Focus}
Since this thesis focuses on the evaluation of \gls{AI}-based red and blue team activities in virtual and physical network environments,
a framework which has a strong focus on networking and is able to run on small embedded devices is required.
\paragraph{Harness Concept}
In the context of \gls{AI}, the term \enquote{harness} is used to describe the software layer surrounding an agent that provides guardrails,
tooling, configuration, logging, monitoring, and other supporting functionality required for secure and reliable operation.
As \gls{NSAK} already acts as a harness for network focused cybersecurity scenarios~\ref{subsec:nsak-usp},
we can implement an \gls{AI} agent and reuse the already implemented tooling.
\paragraph{Familiarity}
The existing familiarity with the \gls{NSAK} framework, its Python based library, and development workflow,
which allows us to efficiently extend the core and develop new scenarios and drills for the library.
\paragraph{Interoperability}
When \gls{NSAK} does not provide specific functionality or when external specialized capabilities are required, other frameworks can be modular integrated via their \glspl{API}
to call specific functionalities in drills and scenarios.

The following chapter therefore introduces the core concepts of \gls{NSAK}, inherited from the predecessor project~\cite{nsakRepository2026}
and extended in this thesis, which are forming the basis for the implementation presented in~\ref{ch:implementation}.
