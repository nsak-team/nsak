\subsubsection{Create New Resource Type: Device}\label{subsubsec:create-new-resource-type-device}

In the context of \enquote{Project 2}\ref{sec:predecessor-project-enquote-project-2} this resource type was already defined conceptionally and the~\gls{BananaPI R4} was added as an example in the library under \texttt{lib/devices/bananapi\_r4/}.
But the resource type was not actually added to the \glsxtrshort{NSAK} core and be able to manage device configurations we need to implement the Device resource type first.
Analog to the other resource types, a yaml specification for defining devices in the library and multiple classes for representing and managing devices in the core are required.
The listing~\ref{lst:device-resource-yaml-specification} shows the initial specification for a device resource, which will get extended later on with a section for configuration management.

\begin{lstlisting}[language=bash,caption={Device Resource YAML Specification},label={lst:device-resource-yaml-specification}]
device: <str:resource-version>

metadata:
  id: <str:device-id>
  name: <str:device-name>
  description: <str:device-description>
  author: <str:author-email>
  repository: <str:resource-repository>
\end{lstlisting}

In the following table~\ref{tab:device-resource-classes} the required Python classes are listed and described.
The classes will be located under \texttt{src/nsak/core/device} within their respective files.

\begin{table}[h]
    \centering
    \begin{tabularx}{\textwidth}{llX}
        \hline
        \textbf{Class} & \textbf{File Name} & \textbf{Description} \\
        \hline
        Device & device.py & A dataclass, which represents a device resource as objects during runtime (usually quite similar to the yaml specification). \\
        DeviceLoader & device\_loader.py & This class returns Device objects and is used by the DeviceManager to find and load device resources from the library. \\
        DeviceManager & device\_manager.py & The manager class implements the business logic and exposes an API, which can be used by the \glsxtrshort{CLI}. \\
        \hline
    \end{tabularx}
    \caption{Device Resource Classes}
    \label{tab:device-resource-classes}
\end{table}

In \enquote{Project 2}\ref{sec:predecessor-project-enquote-project-2} it became already clear, that the described classes share a lot of boilerplate code between each other.
For this reason the base classes described in~\ref{tab:device-resource-classes} where added to get rid of the duplicated logic, which leads to better compliance with the \gls{DRY} principles.
The classes will be located under \texttt{src/nsak/core/resource} within their respective files.

\begin{table}[h]
    \centering
    \begin{tabularx}{\textwidth}{llX}
        \hline
        \textbf{Class} & \textbf{File Name} & \textbf{Description} \\
        \hline
        Resource & resource.py & Base class for all resources: Scenario, Drill, Environment and Device. \\
        ResourceLoader & resource\_loader.py & Base class which handles searching and loading resources from the filesystem. \\
        ResourceManager & resource\_manager.py & Base class which defines common methods for all resource manager classes. \\
        \hline
    \end{tabularx}
    \caption{Resource Python Classes}
    \label{tab:resource-base-classes}
\end{table}

To complete the integration of the device resource, the new functionality must be exposed via \glsxtrshort{CLI}.
The available bash commands are shown in the following listing~\ref{lst:nsak-cli-list-devices}.

\begin{lstlisting}[language=bash,caption={NSAK CLI: List Devices},label={lst:nsak-cli-list-devices}]
# Show usage, options and subcommands for the device resource
nsak device --list

# List all devices found in the resource library
nsak device list

# Output:
❯ nsak device list
ID           NAME         PATH
bananapi_r4  BananaPI R4  /home/lukas/CLionProjects/swiss-army-knife-network-sniffer/lib/devices/bananapi_r4
\end{lstlisting}
