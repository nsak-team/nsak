\textbf{Limitation:} Traditional Recon returns a structured \texttt{NetworkDiscoveryResultMap}, whereas AI Recon returns \texttt{None} (log stream only).
A direct comparison of results therefore requires either parsing the AI output or documenting this asymmetry as a limitation.

\section*{Qualitative Criteria}

\begin{itemize}
	\item \textbf{Speed:} Time from scenario start to complete output of all discovered hosts and services
	\item \textbf{Correctness:} Share of correctly identified hosts and services compared to the ground truth
	\item \textbf{Initial knowledge (pre-conditions):} Which assumptions does the scenario require (interface, subnet)?
	\item \textbf{Creativity:} Does AI Recon identify relationships or suggest follow-up steps not covered by Traditional Recon?
	\item \textbf{Token usage:} Number of tokens consumed per run (AI Recon only)
	\item \textbf{Hallucination:} Hosts or services in the output that do not exist in the environment
	\item \textbf{Task completion:} Do both scenarios complete the task fully?
\end{itemize}

\section*{Quantitative Criteria}

\begin{itemize}
	\item \textbf{Consistency:} How much does the output vary across $n = 10$ runs with an identical prompt, per model and environment?
	\item \textbf{Prompt sensitivity:} How does the model respond to minimally altered prompts (e.g.\ a different interface name)?
\end{itemize}

With 3 models $\times$ 3 environments $\times$ $n = 10$ runs, this yields 90 measurements for AI Recon.
