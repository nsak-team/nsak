\section{AI \textendash Scenarios}\label{sec:ai-scenarios-implementation}

This section describes the design and implementation of the milestone \gls{AI} Scenarios~\ref{subsubsec:milestone-ai-scenarios},
which is based on the user story map workshop \gls{AI} Purple Team~\ref{subsec:nsak-scenario-ai-purple-team}.
In the workshop we defined the features which such a scenario may provide and categorized them in \enquote{Must}, \enquote{Could} and \enquote{Should}.
Because of time constraints, we set the focused only on the user stories categorized as \enquote{Must}.
The main goal is to implement an \gls{AI} reconnaissance scenario, which is described in the~\ref{subsec:scenario-ai-reconnaissance}.
But on the way it made sense to also create an intermediary scenario which can run custom prompts~\ref{subsec:scenario-ai-agent}.
Further, we already explored the \gls{AI} based intrusion detection scenario~\ref{subsec:scenario-ai-intrusion-detection} which should be seen as proof of concept, because the corresponding milestone and goals are categorized as \enquote{Should}.

\subsection{\gls{AI} Agent}\label{subsec:ai-scenarios-implementation-ai-agent}

An \gls{AI} agent is an autonomous system that combines a large language model (\gls{LLM}) with a set of tools it can invoke to accomplish a goal.
Rather than just generating text, the agent follows a reasoning loop: it plans which tool to call, executes it,
observes the result, and continues until the task is complete~\cite{the-rise-of-agentic-ai}.

The project team chose \href{https://www.langchain.com/}{LangChain} as the agentic framework without comparing it with alternative solutions, for the following reasons:

\begin{itemize}
    \item Free and open-source
    \item Python package with native integration into the project's toolchain
    \item Suggested by various sources and has a good reputation in the community
    \item Extensive documentation and active community support
\end{itemize}

For the integration into the \gls{NSAK} framework we decided to implement an \mintinline{python}{AiAgent} class as the central abstraction,
which wraps a \mintinline{python}{BaseChatModel} together with a set of LangChain tools and delegates the reasoning loop to LangChain's built-in \mintinline{python}{create_agent()}.

\subsection{LangChain Concepts}\label{subsec:ai-scenarios-langchain-concepts}

LangChain provides a framework for developing applications powered by large language models (\gls{LLM}s) and agent-based systems.
It enables developers to combine modular components and external integrations, simplifying \gls{AI} application design while maintaining flexibility as underlying technologies evolve~\cite{langchain_repo}.

The primary LangChain concepts used in the \gls{NSAK} framework are:

\begin{itemize}
    \item \mintinline{python}{BaseChatModel} - provider-agnostic interface for the underlying \gls{LLM}.
    \item \mintinline{python}{BaseTool} - interface for callable tools that the agent can invoke.
    \item \mintinline{python}{create_agent()} - builds a LangGraph-based ReAct agent graph that wires the model and tools together.
    \item \mintinline{python}{messages} - a list of conversation messages (user, \gls{AI}, tool) maintained across the agent's reasoning loop.
\end{itemize}

\begin{listing}[H]
    \inputminted{python}{../../../src/nsak/core/ai/ai_agent.py}
    \caption{LangChain: AI Agent}
    \label{lst:langchain-agent}
\end{listing}

The \mintinline{python}{AiAgent.__init__()} method calls \mintinline{python}{create_model()} to instantiate the provider-specific chat model
and then passes it to \mintinline{python}{create_agent()} together with the tool list and a fixed system prompt that establishes the cybersecurity simulation context.
The \mintinline{python}{run()} method invokes the agent once and streams all resulting messages (user, \gls{AI}, tool calls, tool results) as formatted strings.
The \mintinline{python}{run_interactive()} method extends this into an interactive loop,
where after each agent response the operator is prompted for the next instruction,
and the full conversation history is retained in the \mintinline{python}{messages} list until the operator types an empty line or \mintinline{bash}{exit}.

\subsubsection{Tool Calling Concepts}\label{subsubsec:ai-agent-tool-calling-concepts}

Tool calling is the mechanism by which the \gls{LLM} declares that it wants to invoke an external function.
The framework intercepts the model's output, parses the tool call, executes the corresponding Python function, \gls{MCP}, or Skill,
and appends the result to the message history before asking the model to continue.
This loop repeats until the model produces a final text response with no tool calls.

In \gls{NSAK}, tools can be provided through several complementary mechanisms:

\begin{itemize}
    \item \textbf{LangChain Tools} - native Python functions decorated with \mintinline{python}{@tool},
    which LangChain automatically wraps with type-safe JSON schemas for the model.
    This is the primary mechanism used for \gls{NSAK}-specific tools (host configuration, \gls{CLI} access, e-mail, human interaction hook).
    Further, all \gls{NSAK} drills are wrapped as LangChain tools via \mintinline{python}{generate_drill_tools()},
    giving the agent type-safe access to all drill capabilities.
    \item \textbf{\gls{MCP}} - the Model Context Protocol allows external tool servers to expose additional capabilities;
    used here for the draw.io integration (see~\ref{subsubsec:ai-agent-mcp-integration}).
    \item \textbf{\gls{CLI} Access} - the \mintinline{python}{cli_tool} gives the agent direct shell access,
    allowing it to run any installed binary (nmap, tshark, etc.).
\end{itemize}

\subsubsection{MCP Integration}\label{subsubsec:ai-agent-mcp-integration}

The \gls{MCP}~\cite{anthropic-mcp} is an open protocol that standardises how \gls{AI} models connect to external tool servers.
Rather than implementing tool calling ad-hoc, \gls{MCP} servers expose a well-defined interface that any compatible \gls{LLM} framework can consume~\cite{mcp-landscape}.
LangChain Agents must be invoked in an event loop to properly support \gls{MCP}, this forced us to refactor the implementation \enquote{ai\_agent.py} to be async.
Further we need to add support for async drills and scenarios, as otherwise we could not run the \gls{AI} agent inn those contexts.

\gls{NSAK} integrates an external draw.io \gls{MCP} server to allow the \gls{AI} agent to create and manipulate diagrams during a scenario run.
The client is initialised at module level (listing~\ref{lst:ai-provider-map}, lines 41--51 using \mintinline{python}{MultiServerMCPClient} from \mintinline{bash}{langchain-mcp-adapters}, pointing to \mintinline{bash}{https://drawio.hiube.ch/mcp} with Basic authentication.

\gls{MCP} tools are loaded asynchronously inside \mintinline{python}{create_ai_agent()} and appended to the tool list.
If the server is unavailable, the exception is caught and logged as a warning so the scenarios can still run without diagram support.

\subsection{CLI Kill Switch}\label{subsec:ai-scenarios-implementation-cli-kill-switch}
It's possible that an \gls{AI}-Agent starts doing unexpected, unwanted or even destructive actions.
This was also identified as a possible risk in the risk assessment~\ref{subsec:risk_assessment}.
This kind of misbehavior, combined with elevated permissions and tool calling capabilities via direct \gls{CLI} access,
could lead to a wide range of issues:

\begin{itemize}
    \item The \gls{AI}-Agent is stuck in a loop while using most system resources.
    \item The \gls{AI}-Agent misconfigures the system, rendering it inaccessible or even unusable.
    \item The \gls{AI}-Agent burns too many \gls{API} credits because of a bug, an inefficient request, or a huge task.
    \item The \gls{AI}-Agent starts an attack against a production network.
\end{itemize}

For these reasons we want to be able to kill a specific or all scenarios as fast as possible.
As a first measure, the project team decided to add this functionality as simple \gls{CLI} commands:

\begin{itemize}
    \item \mintinline{bash}{nsak scenario kill <scenario-id>}: Kill a specific scenario (sends \mintinline{bash}{SIGTERM} to the container)
    \item \mintinline{bash}{nsak scenario killswitch}: Kill all running scenarios
    \item \mintinline{bash}{nsak killswitch}: Alias for \mintinline{bash}{nsak scenario killswitch}
\end{itemize}

\subsection{Scenario: AI Reconnaissance}\label{subsec:scenario-ai-reconnaissance}

The \gls{AI} Reconnaissance scenario automates host and service discovery on a specified network interface.
It encodes a structured five-step plan directly into the initial prompt: the agent is instructed to call \mintinline{python}{host_configuration} to determine the \gls{IP} addresses and subnets on the interface, then use the \mintinline{python}{cli} tool to invoke nmap for host scanning, then again for service enumeration, and finally to report all findings including vulnerability indicators.
If the \mintinline{python}{interactive} flag is set, the last step invites the operator to issue follow-up instructions via the \mintinline{python}{human_interaction_hook}.

This prompt-driven approach means the scenario does not contain any network scanning logic itself - the agent decides which nmap flags to use, how to interpret results, and what to scan next.

\subsection{Scenario: AI Intrusion Detection}\label{subsec:scenario-ai-intrusion-detection}

The \gls{AI} Intrusion Detection scenario is a proof of concept, as it was specified as \enquote{Should} goal.
It demonstrates a two-phase approach: first it performs host discovery using \mintinline{python}{DrillManager.execute("discover_hosts")},
then it captures live network traffic using \mintinline{bash}{tshark} (a system dependency declared in the scenario \gls{YAML}).
Up to 200 packets are captured over a 60-second window and extracted as \gls{CSV} fields (frame number, source and destination \gls{MAC}, source and destination \gls{IP}, \gls{TCP}/\gls{UDP} destination port, protocol stack, and frame length).

Both the host discovery table and the packet \gls{CSV} are injected into a structured \mintinline{python}{PROMPT_TEMPLATE} that instructs the \gls{AI} to identify at most five suspicious events, each with source/destination \gls{IP} and \gls{MAC}, protocol, and the reason for suspicion, and to identify any malicious hosts.
By constraining the number of events the prompt keeps the agent's output concise and actionable.
