\section{Agile Management Process}\label{sec:agile-management-process}

The project followed an interactive development approach using Gitlab for issue tracking and planning.
We defined our project management in a Scrum-like manner, but we individualized the process according to the projects scope and our needs.
Work items where organized into epics, milestones and issues.
Each iteration lasts two weeks.
We decided to hold the following Scrum ceremonies after each sprint:

\subsection{Definition of Done (DoD)}\label{subsec:definition-of-done}
\begin{table}[H]
	\centering
	\begin{tabularx}{\textwidth}{lX}
		\toprule
		\textbf{Category} & \textbf{Criteria} \\
		\midrule
		Implementation &
		\begin{itemize}
			\item All acceptance criteria fulfilled
			\item Container execution verified
			\item Pre-commit hooks pass
			\item Logging and error handling consistent
		\end{itemize} \\

		Testing &
		\begin{itemize}
			\item Feature or bug fix tested
			\item Acceptance criteria verifiable (automated or manual)
			\item Relevant edge cases considered
			\item Execution reproducible
		\end{itemize} \\

		Documentation &
		\begin{itemize}
			\item README updated if required
			\item Architecture changes documented
			\item Thesis relevance briefly noted
			\item Limitations documented
			\item Required documentation stored for thesis or appendix
		\end{itemize} \\
		\bottomrule
	\end{tabularx}

\section{Planning and Estimation}\label{sec:planning-and-estimation}

The following estimation strategy was used:

\begin{itemize}
	\item 1 hour corresponds roughly to 1 weight point
	\item Iteration length: 2 weeks
	\item Weights per iteration: ~40h per person = ~80 weight per iteration
	\item Sprint planning duration: 1.5 hours per iteration
	\item Sprint review duration: 1 h per iteration
	\item Sprint retro duration: 1 h per iteration
\end{itemize}
